Methodology

Transparent documentation of how data is collected, cleaned, interpreted, and stored. Science should be reproducible.

Sensor hardware

The primary monitoring platform uses two sensor models manufactured by PurpleAir/AirAssure:

  • Bluesky 8143 (outdoor) — measures PM1, PM2.5, PM4, PM10 via laser particle counting, plus temperature, relative humidity, and barometric pressure.
  • Air Assure 8144 (indoor) — same PM channels plus CO₂ (NDIR) and total VOC.

Both instruments use a Sensirion SPS30 optical particle counter and report at approximately 1-minute intervals when online. These are research-grade low-cost sensors and are not reference instruments. They have not been collocated with regulatory monitors for formal correction factor derivation at these sites.

Data collection

Sensors upload readings via Wi-Fi to a cloud API. Our ingestion pipeline polls the API or processes CSV exports on a scheduled basis. Every ingestion attempt is logged to the IngestionLog table, including failures. Sensors may go offline due to:

  • Power outages (load shedding is common in rural Nepal)
  • Internet connectivity loss
  • SD card or firmware errors
  • Physical damage or maintenance

Quality flags

Every reading is assigned one of the following quality flags:

Flag Meaning
GOODValue within expected range, no anomalies detected.
SUSPECTValue flagged as potentially erroneous (e.g. PM2.5 > 500 µg/m³, all channels simultaneously zero).
BADKnown sensor malfunction period or calibration error.
MISSINGGap in the expected reporting sequence.
UNVALIDATEDNewly ingested reading, not yet reviewed.

Raw values are never overwritten. All cleaning and calibration writes to a separate cleaned_value column. The raw reading is permanently preserved.

PM₂.₅ interpretation

PM₂.₅ (particulate matter smaller than 2.5 µm) is used as the primary exposure indicator because it is most strongly linked to respiratory and cardiovascular health outcomes. We display values in µg/m³ and compare to two guidelines:

  • WHO 2021 guideline: 24-hour mean ≤ 15 µg/m³; annual mean ≤ 5 µg/m³.
  • Nepal NAAQS (National Ambient Air Quality Standard): 24-hour mean ≤ 40 µg/m³.

Low-cost optical particle counters can undercount or overcount PM depending on particle composition, humidity, and temperature. High relative humidity (> 85%) can cause hygroscopic growth of particles, artificially inflating PM readings. We do not apply humidity corrections at this stage; this is a documented limitation.

Indoor/outdoor comparison

We compute hourly median values for matched indoor and outdoor sensors at the same site. The indoor/outdoor (I/O) ratio is computed as: I/O = PM₂.₅_indoor / PM₂.₅_outdoor, using matched hours only. Statistical significance of the difference is tested using the Wilcoxon signed-rank test (non-parametric, because PM₂.₅ is not normally distributed). Effect size is reported as rank-biserial correlation.

Data completeness

Completeness is computed per sensor per day as: (observed readings) / (expected readings based on nominal reporting interval). We use a 1-minute expected interval for these sensors. A day is classified as:

  • High completeness (≥ 80%): Green
  • Moderate completeness (50–79%): Amber
  • Low completeness (< 50%): Red

Population exposure estimates

Population exposure is estimated using a simple nearest-sensor assignment:

  1. District centroids are calculated from 2021 Nepal Census district boundaries.
  2. Each district centroid is assigned the PM₂.₅ value from its nearest sensor (haversine distance).
  3. Confidence is assigned based on sensor distance and data completeness.

This is an approximation, not a precise exposure model. It does not account for population density within districts, topography, source proximity, indoor time, or inter-district variation. Do not use for regulatory or health-intervention decisions without independent validation.

Code and reproducibility

The full data pipeline, ingestion framework, and analysis code are available on GitHub. Each ingestion run is logged with source file, converter class, records saved, duplicates, and errors. Notebooks used for exploratory analysis (e.g. Belauri indoor/outdoor comparison) are stored alongside the codebase.
