Authentication

API key (recommended for programmatic access)

Pass your key in the X-API-Key request header. Keys are issued from Portal → API Keys. 

curl -H "X-API-Key: <your-64-char-key>" \
     "https://your-domain/api/v1/sensors/"

Keys are stored as PBKDF2-SHA256 hashes — the raw key is shown once at creation and never again.

Session auth (browser / Django admin)

Sign in at /users/login/. Subsequent requests carry the session cookie automatically. Session auth grants the same permissions as an API key matching your user role.

{# ── Permission tiers ───────────────────────────────────────────────── #}

Permission tiers

Every endpoint requires a minimum privilege level. The tiers are additive — a higher tier includes all lower-tier capabilities.

Tier API key role Session user role Grants
Public None required None required Read sensors, sites, charts
Sensor SENSOR or ADMIN ADMIN session POST live & batch readings, self-register sensor
Researcher RESEARCHER or ADMIN RESEARCHER / MAINTAINER / ADMIN Query & export readings
Admin ADMIN only ADMIN only Create / update / delete sensors & sites; trigger aggregation

ADMIN API keys can only be issued by a Django superuser from the admin panel. SENSOR and RESEARCHER keys can be self-served from Portal → API Keys.

Sensor endpoints SENSOR key

Submit live reading

Single timestamp from a live sensor. serial_number can be omitted when the key is bound to a specific sensor. 

POST /api/v1/readings/
X-API-Key: <sensor-key>
Content-Type: application/json

{
  "serial_number": "81432434001",
  "timestamp": "2026-05-29T08:00:00Z",
  "readings": [
    {"pollutant": "PM25", "value": 45.2, "unit": "µg/m³"},
    {"pollutant": "TEMP", "value": 18.5, "unit": "°C"}
  ]
}

Submit batch readings (offline catch-up)

Up to 10,000 snapshots per request. Duplicate timestamps are silently skipped and counted in the response.

POST /api/v1/readings/batch/
X-API-Key: <sensor-key>
Content-Type: application/json

{
  "serial_number": "81432434001",
  "readings": [
    {
      "timestamp": "2026-05-29T08:00:00Z",
      "measurements": [{"pollutant": "PM25", "value": 45.2, "unit": "µg/m³"}]
    },
    {
      "timestamp": "2026-05-29T08:01:00Z",
      "measurements": [{"pollutant": "PM25", "value": 47.1, "unit": "µg/m³"}]
    }
  ]
}

Response: { "snapshots": N, "saved": N, "duplicates": N, "errors": N }

Self-register a sensor

Idempotent — returns 200 if already registered, 201 if created.

POST /api/v1/sensors/register/
X-API-Key: <sensor-key>
Content-Type: application/json

{
  "serial_number": "81432434001",
  "friendly_name": "Belauri Outdoor",
  "model": "8143",
  "site": 1,
  "is_indoor": false,
  "power_type": "SOLAR",
  "connectivity_type": "WIFI"
}

Researcher endpoints RESEARCHER key

Query readings

GET /api/v1/readings/?sensor=1&pollutant=PM25&start=2026-01-01&end=2026-04-01&quality=GOOD
Param Required Description
sensorNoFilter by sensor ID
pollutantNoPM25, PM10, TEMP, RH, CO2, …
start / endNoISO 8601 datetime
qualityNoGOOD / SUSPECT / BAD / UNVALIDATED (default: all)
indoorNotrue or false
page / page_sizeNoPagination; max page_size = 10,000

Export readings (CSV / JSON)

GET /api/v1/export/?sensors=1,2&pollutants=PM25,PM10&data_type=raw&output=csv
GET /api/v1/export/?sensors=1&data_type=daily&start=2026-01-01&output=json
Param Required Description
sensorsYesComma-separated sensor IDs, e.g. 1,2,3
pollutantsNoComma-separated codes (default: all)
data_typeNoraw (default) / hourly / daily
start / endNoISO 8601 datetime — researcher+ only
qualityNoGOOD (default) / ALL / SUSPECT / BAD
outputNocsv (default) / json
columnsNoComma-separated column names to include

Row limits: public 500 · researcher 50,000 · admin 500,000. Configurable in Django admin → Analysis → Download Configuration.

{# ── Admin endpoints ─────────────────────────────────────────────────── #}

Admin management endpoints ADMIN key only

These endpoints are for programmatic provisioning of sensors and monitoring sites. They require an ADMIN-role API key (or an admin browser session). ADMIN keys must be issued by a Django superuser.

{# Sites #}

Monitoring sites (locations)

Create a site

POST /api/v1/sites/
X-API-Key: <admin-key>
Content-Type: application/json

{
  "name": "Belauri",              // required, must be unique
  "district": "Dadeldhura",       // required
  "municipality": "Ajaymeru",
  "province": "Sudurpashchim",
  "latitude": 29.4931,            // required — WGS 84 decimal degrees
  "longitude": 80.5741,           // required
  "elevation_m": 1250,
  "population_estimate": 4800,
  "land_use_type": "RESIDENTIAL", // RESIDENTIAL|AGRICULTURAL|FOREST|URBAN|INDUSTRIAL|MIXED|OTHER
  "description": "Near primary school."
}

Returns 201 Created with the full site object.

Update / delete a site

PUT    /api/v1/sites/{id}/   # full replacement (all fields)
PATCH  /api/v1/sites/{id}/   # partial update (only provided fields change)
DELETE /api/v1/sites/{id}/   # 204 No Content; blocked if sensors are linked (409 Conflict)
{# Sensors #}

Sensors

Create a sensor

POST /api/v1/sensors/
X-API-Key: <admin-key>
Content-Type: application/json

{
  "serial_number": "81432434001",     // required, must be unique
  "friendly_name": "Belauri Outdoor",
  "model": "8143",
  "manufacturer": "Particles Plus",
  "site": 1,                          // required — Site ID
  "is_indoor": false,
  "power_type": "SOLAR",              // GRID|SOLAR|BATTERY|UNKNOWN
  "connectivity_type": "WIFI",        // WIFI|CELLULAR|LORA|MANUAL|UNKNOWN
  "status": "ACTIVE",                 // ACTIVE|OFFLINE|MAINTENANCE|DECOMMISSIONED
  "installed_at": "2025-11-01T00:00:00Z",
  "installation_notes": "",
  "calibration_field_notes": ""
}

Returns 201 Created.

Update a sensor

PUT    /api/v1/sensors/{id}/   # full replacement
PATCH  /api/v1/sensors/{id}/   # partial update — e.g. {"status": "OFFLINE"}

Decommission / delete a sensor

DELETE /api/v1/sensors/{id}/            # soft — sets status=DECOMMISSIONED, preserves readings
DELETE /api/v1/sensors/{id}/?hard=true  # hard — removes DB row (blocked if readings exist)
Prefer soft-decommission. Hard delete will fail with a database error if any CanonicalReading rows reference the sensor (Django PROTECT constraint). This is intentional — it prevents accidental loss of historical data.
{# Aggregation #}

Trigger aggregation recompute

Recalculates HourlyAggregate and DailyAggregate from raw readings. Both fields are optional. Also available from Portal → Aggregation. 

POST /api/v1/aggregate/
X-API-Key: <admin-key>
Content-Type: application/json

{
  "sensor_id": 1,          // omit to recompute all sensors
  "since": "2026-01-01"    // omit to recompute everything
}

Response: { "sensors_processed": N, "hourly_rows": N, "daily_rows": N, "errors": N }

{# ── Quality flags ───────────────────────────────────────────────────── #}

Quality flags

Raw values are never overwritten. QC corrections are written to cleaned_value. Charts and exports use cleaned_value ?? raw_value.

Flag Badge Meaning
GOOD Good Passes all automated QC checks
UNVALIDATED Unvalidated Not yet checked — default for new readings
SUSPECT Suspect Passes range check but flagged by anomaly detector
BAD Bad Fails physical bounds or confirmed outlier
MISSING Missing Expected timestamp with no measurement
{# ── Sensor status ───────────────────────────────────────────────────── #}

Sensor status values

Status Badge Meaning
ACTIVE Active Collecting and transmitting data
OFFLINE Offline Not sending data; cause unknown
MAINTENANCE Maintenance Under servicing; data may be unreliable
DECOMMISSIONED Decommissioned Retired; historical readings preserved

{# ── Python example ──────────────────────────────────────────────────── #}

Python example

import requests

BASE = "https://your-domain"
HEADERS = {"X-API-Key": "your-admin-key-here"}

# ── Create a monitoring site ──────────────────────────────────────────────────
site = requests.post(f"{BASE}/api/v1/sites/", headers=HEADERS, json={
    "name": "Kathmandu Central",
    "district": "Kathmandu",
    "municipality": "Kathmandu Metropolitan",
    "latitude": 27.7172,
    "longitude": 85.3240,
    "land_use_type": "URBAN",
}).json()
print(f"Site created: id={site['id']}")

# ── Create a sensor at that site ──────────────────────────────────────────────
sensor = requests.post(f"{BASE}/api/v1/sensors/", headers=HEADERS, json={
    "serial_number": "99999999001",
    "friendly_name": "KTM Outdoor",
    "model": "8143",
    "site": site["id"],
    "is_indoor": False,
    "power_type": "GRID",
    "connectivity_type": "WIFI",
    "status": "ACTIVE",
}).json()
print(f"Sensor created: id={sensor['id']}")

# ── Update sensor status to OFFLINE ──────────────────────────────────────────
requests.patch(
    f"{BASE}/api/v1/sensors/{sensor['id']}/",
    headers=HEADERS,
    json={"status": "OFFLINE"},
)

# ── Export PM2.5 data for the sensor ─────────────────────────────────────────
resp = requests.get(
    f"{BASE}/api/v1/export/",
    params={"sensors": sensor["id"], "pollutants": "PM25",
            "quality": "GOOD", "start": "2026-01-01", "output": "csv"},
    headers=HEADERS,
)
with open("pm25.csv", "wb") as f:
    f.write(resp.content)
print(f"Downloaded {len(resp.content):,} bytes")
